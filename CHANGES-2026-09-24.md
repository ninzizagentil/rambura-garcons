# Changes — 24 Sep 2026

## Do these yourself after unzipping
1. `backend/.env`: fill `SMTP_USER`, `SMTP_PASSWORD` (Gmail App Password) and `SMTP_FROM`, or save SMTP settings in Admin > Settings. Without them no e-mail is sent (forgot password answers 200 but nothing arrives; the reason is printed in the API console).
2. If an earlier zip was shared, create new `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET`. Everyone signs in once again after this update (session storage changed).
3. Git clean-up: `git rm -r --cached .kilo` then delete the `.kilo` folder. Delete old files in `backend/backups/` (211 MB) and the root `backups/` folder.
4. Existing data: `npm --prefix backend run fix:image-urls` (dry run), then add `-- --apply`. Same idea for `fix:phones`.
5. Test the report pages on real MongoDB (library, stock, equipment reports; edit user). They could not be run in my test database.
6. Production with Docker: `docker compose up -d --build`. To seed a NEW database, run the seed from the server itself (the database port is open on 127.0.0.1 only):
   - Linux/Mac: `SEED_CONFIRM_WIPE=yes NODE_ENV=production npm --prefix backend run seed`
   - Windows PowerShell: `$env:SEED_CONFIRM_WIPE="yes"; $env:NODE_ENV="production"; npm --prefix backend run seed`
   It prints random passwords once and skips demo data (add `SEED_DEMO=true` to include it).

## Part 1 - fixes from the problem report
- Seed no longer crashes; stock Archive Requests now have a backend (`/api/stock/archive-requests`); the stock "Delete" menu opens the archive request page.
- `fix-phones.js` restored (helpers added to `validators.js`); new `fix:image-urls` script.
- E-mail: needs host + user + password; 10 s timeouts; admin Settings SMTP is really used (password encrypted); notification e-mails no longer block applicants.
- Forgot password: same answer for every email. Login: rejects non-text input.
- Sessions: one refresh token per device (SHA-256), idle timeout enforced on refresh, logout signs out only that device, activity saved at most once a minute.

- Permissions: new `stock.reconcile.approve` (management), supplier reads need `stock.view`; a server restart no longer resets role edits (only adds new default permissions).
- Validation: Foods need a batch number; gallery needs a caption; uploads over 5 MB answer 413.
- Backups: all collections, newest 7 kept, streamed, private file mode, not on every restart.
- Login page: demo accounts and the one-click admin login exist only in development builds.
- Deploy: production mode and proxy trust forced in docker-compose, nginx accepts 10 MB, image URLs stored as `/uploads/...`, `.dockerignore` / `.gitignore` updated, `.env.example`, README and API docs updated.
- Tests: `npm test` runs all frontend test files (15); backend has 19 tests (6 new).

## Part 2 - public website scrolling, demo data for every panel, terminal (proxy) problems
- **Footer shown first on every menu page:** the app never reset the scroll position when the page changed, so a short page opened already scrolled to the footer. New `ScrollToTop` component (in `main.jsx`): new page = start at the top; `#section` links scroll to the section; Browser Back keeps the old position.
- **Demo data in every panel** (`npm --prefix backend run seed`, development): `backend/src/seed/demoData.js` adds books + loans (5 overdue), suppliers, 24 stock items with 70 movements (low stock, expiring/expired food, out of stock), damaged and disposed stock, 4 reconciliations, stock/equipment archive + retirement requests in every state, 16 equipment items, 14 applications in every status, events, contact messages, notifications for each role, activity log and reports. Extra accounts (password `Demo@12345`): `librarian2`, `registrar`, `stock2` (inactive). In production it is skipped unless `SEED_DEMO=true`.
- **Panel check:** every panel endpoint was called as each role against this data: 56 OK. The only 7 that could not run are report queries my test database does not support (`$lookup`, `$dateToString`); test the report pages on your MongoDB.
- **Terminal / proxy problems found and fixed:**
  1. Backend stopped or restarting: Vite printed a long `http proxy error` stack for EVERY request (the app polls every few seconds). Now one short `[proxy]` explanation with the 3 usual causes, and the browser gets a clear 503 "The backend server is not running".
  2. The proxy used `localhost`, which some computers resolve to IPv6 (`ECONNREFUSED ::1:5000`). Now `127.0.0.1`, changeable with `BACKEND_URL` (for example if port 5000 is taken).
  3. Every login and every action of librarian, stock and equipment users sent `GET /activity` and got 403 (they lack `audit.view`), which also forced a permission re-sync each time. Those roles no longer send it.
  4. `wait-for-backend` now explains why the backend did not start (MongoDB, `.env`, port).
  5. Vite silently moved to port 5174 when 5173 was busy (password-reset links and CORS expect 5173). It now stops with a clear message.
  6. Seed: restored the `siteImages` line and the archive-request wipe that my test workaround had removed.
- Docker: MongoDB is published on `127.0.0.1` only (needed to run the seed from the server); README has a "Troubleshooting the terminal" table.
